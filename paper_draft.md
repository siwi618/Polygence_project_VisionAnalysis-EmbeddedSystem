# Lightweight Image Classification for Museum Artifact Recognition on Raspberry Pi 5: Custom CNN vs. MobileNetV2 with TFLite Quantisation

## Abstract
This study compares two image classification models: a custom CNN and MobileNetV2, both converted to TensorFlow Lite (TFLite) with fp16 quantisation, and deploys a TFLite model on an embedded system to personalise museum experiences. The embedded system that the two models are deployed on is a Raspberry Pi 5 single board to evaluate the feasibility for an embedded museum application. In the final comparison, the CNN fp16 achieved an accuracy of 85.37%, compared with 90.24% for MobileNetV2.On the Raspberry Pi 5, the CNN achieved a lower inference time of 6.79 ms/image, compared with 11.65 ms/image for MobileNetV2. FP16 quantisation reduced the model sizes to 6.3 MB for the CNN and 4.3 MB for MobileNetV2, respectively. Hence, these results show that the deployment of the CNN on the Raspberry Pi 5 is feasible, but MobileNetV2 provides a better overall trade-off between accuracy and model size.

## 1 Introduction
In traditional museum operations, museums often guide clients in groups. The problem caused by this is that different clients are interested in different artifacts. Group guides may not have enough energy to serve everyone in the group. As a result, this paper aims to use lightweight image classification in embedded systems to give all clients a unique museum experience. The main problem is that it's hard to run deep learning models on embedded systems due to resource constraints. This paper asks: Can a lightweight image classification model, trained on a custom museum dataset, be deployed on a Raspberry Pi for real-time artifact recognition, and how does a custom CNN perform compared to MobileNetV2 in accuracy, size, and inference speed? I collected five artifacts in Suzhou Museum West: they are a bronze bowl, a crystal cup, a fish fan, a jade figure and a pen container. All of them have about 40 images each. I trained a custom CNN and a MobileNetV2 model based on this dataset and compared their performance. Then I validated that the performance of both models remained the same after TFLite quantisation. In the end, both models were successfully deployed on the Raspberry Pi 5 embedded systems.

## 2 Background
Ray (2021) conducts a systematic review, including surveying the hardware and software frameworks, model compression techniques like quantisation, pruning, knowledge distillation and application domains that let deep learning models run directly on resource-constrained embedded systems and microcontrollers. This provides the context for this paper: quantisation is one of the key compression methods discussed in Ray's review. Although Ray (2021) covers a wide range of topics, it lacks embedded systems applications in museum scenarios, while this is the direction of this paper. 

This paper chooses MobileNetV2 as the comparison model because it is an accepted framework designed for resource-constrained embedded systems. Sandler et al. (2018) built MobileNetV2 around inverted residual and linear bottleneck, maintaining high classification accuracy while significantly reducing parameters and computing complexity. Hence, MobileNetV2 can be compared fairly with the custom CNN. Sandler et al. (2018) also did not deploy it on real embedded systems, and this paper can fill this gap.

Bermeitinger et al. deploy a CNN for classifying museum artifacts, which is the same scenario as in this paper, dealing with the problem of small image data volume and difficult labelling of artifacts. On the one hand, it proves that museum artifact recognition is an image classification scenario that has been recognised by academia and has practical significance. On the other hand, Bermeitinger et al. focus more on classification accuracy and cultural heritage search itself, while this paper consider light weight embedded systems deployment issue. 

## 3 Methods

## 3.1 Dataset
The dataset this paper uses consists of five artifacts collected at Suzhou Museum West in Suzhou, China: they are a bronze bowl, a crystal cup, a fish fan, a jade figure and a pen container. In the first two runs, each artifact has around 40 images, while the fish fan only has 20 images because the museum reflected the face of the fan. In the third run, I expanded the fish fan images to 40 by adding 20 images of the other side, since both sides refer to the fan. The training-to-validation split is 8:2, and the seed is 123. One thing to notice is that the size of the image required for the CNN and MobileNetV2 is different: it's 180×180 for the CNN and 160×160 for MobileNetV2. 

## 3.2 Model Architectures
In the custom CNN, it has three Conv2D and MaxPooling2D layer blocks. Conv2D layer extracts features from raw images, such as edges, patterns and shapes, and the MaxPooling2D layer refines feature images to retain the significant features. Flatten layer transforms the three-dimensional feature images into a one-dimensional vector matching the next two Dense layers. The first Dense layer has 128 neurons that can further combine the extracted features and perform the final classification. Because there are 5 types in the dataset, the last layer has 5 neurons, and each neuron gives a result that is a probability corresponding to each category after softmax.

MobileNetV2, as a pre-trained model, has the base model frozen in Phase 1 and adapts the newly added classification head. Then, because of its solid foundation, MobileNetV2 only needs to be fine-tuned from layer 100 in Phase 2 with a lower learning rate.

## 3.3 Training Procedure
The first step for both models is data augmentation because the total data size is about 200, which is still too small to train models. Data augmentation can help to generate more images artificially through flipping, rotation, zooming in and out, and adjusting contrast and brightness. Hence, there is less probability of models memorising the dataset and increased generalisation. Then, a loss function tells models whether their results are correct or not. It can quantify the difference between the model's predictions and the real answers as numbers. What models need to focus on is adjusting parameters to minimise these numbers. After this, Adam, the optimiser I selected, helps the model update the adaptive parameters in the neural network and is widely used for training deep neural networks. Because the dataset used in this paper is too small, it's common to see that validation loss is increasing in the last few epochs, which means the model is overfitting the dataset. My solution is to add early stopping to avoid this. I set patience to five, which means if the validation loss does not improve for 5 consecutive epochs, it will stop training and restore the best weights.

In addition, the learning rate of MobileNetV2 is different in the two phases. In Phase 1, it is 1e-4, and in Phase 2 it is 1e-5. The learning rate in Phase 2 is ten times lower than that in Phase 1 because a whole new classification head is trained from scratch in Phase 1. However, the parameters that need to be fine-tuned in Phase 2 are already trained on ImageNet.

## 3.4 TFLite Conversion
All the original models are Keras models that are relatively large, nearly 40 MB. To apply them in resource-constrained embedded systems, I transform these models into the TFLite format through float16 quantisation. The original models often use 32-bit floating-point to store the weights, and float16 quantisation transforms the numerical representation of these weights into 16-bit floating-point to save computational resources. After testing, the quantisation can reduce the file size of the final models to around 5 MB and maintain the accuracy at the same time.
